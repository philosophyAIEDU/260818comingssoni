# 퍼스널메이커스 독서 챌린지 · 프로세스 이코노미 인증 시스템

구글폼 + 스프레드시트로 운영하던 인증 프로세스를 웹앱으로 옮긴 버전입니다.
빌드 도구 없이 HTML/CSS/JS 파일만으로 동작하며, **현재는 Firebase(Firestore)에 저장**합니다.
저장소가 인터페이스 뒤에 분리되어 있어 `js/config.js`의 `backend` 한 줄로
브라우저 localStorage 모드로 되돌릴 수도 있습니다. (오프라인 시연·테스트용)

- 챌린지 기간 : 2026년 8월 24일(월) ~ 9월 20일(일), 4주 (28일)
- 마감 : 매일 24시 정각, 유예 없음
- 킥아웃 위험 인원 : 누적 미인증 4회부터 (아직 킥아웃 대상은 아닌 경고 단계)
- 킥아웃 : 누적 미인증 6회부터 (개인 사정으로 인증이 어려운 날엔 최소 3주일 전 운영진께 면제 요청)

---

## 실행 방법

정적 사이트라 서버가 없어도 `index.html`을 브라우저로 열면 동작합니다.
다만 파일 경로(`file://`)에서는 클립보드 복사 등 일부 기능이 제한되므로 로컬 서버 사용을 권합니다.

```bash
npx http-server -p 8080 -c-1
# → http://127.0.0.1:8080
```

Netlify(현재 배포 주소: https://comingssoni.netlify.app/)나 GitHub Pages에 올리면 그대로 배포됩니다.

## 화면 구성

### `index.html` — 참가자 인증 화면

| 기능 | 설명 |
| --- | --- |
| 참여 아이디 | 명단에 등록된 이름(실명)을 **한 칸에서 검색하며 선택**. 입력창에 이름이나 초성(예: `ㅍㄹ`)을 치면 바로 아래 목록이 좁혀지고, **Enter·방향키·클릭**으로 고릅니다. 고르고 나면 입력칸 테두리와 `✓ OOO 님으로 선택되었습니다.` 문구로 확정됐음을 알려 줍니다. 화살표 버튼을 누르면 전체 명단이 열립니다. 고르는 방식이라 직접 타이핑한 오타로 집계가 누락될 일이 없습니다 |
| 인증할 날짜 | 기본값은 오늘이지만, **드롭다운으로 다른 날짜를 골라 제출**할 수 있습니다. 자정 직후 제출로 날짜가 하루 밀려서 전날 기록이 다음날 것과 뒤섞이거나 덮어써지는 문제를 막기 위한 기능입니다 — 다만 마감을 넘긴 날짜로 제출해도 **미인증(X)으로 계속 집계**됩니다 (아래 [지각 제출 처리 방식](#지각-제출-처리-방식) 참고). |
| 인증 2항목 | 오늘 읽은 챕터에서 가장 인상 깊었던 핵심 내용 / 오늘 책을 읽고 느낀 점(적용할 점) — 입력을 최소화하기 위해 챕터 입력란은 없앴습니다 |
| 마감 카운트다운 | 24시까지 남은 시간을 실시간 표시 |
| 같은 날짜 재제출 | 새 인증이 쌓이지 않고 **기존 인증을 수정**합니다 (별도의 삭제 버튼은 없고, 다시 작성해 제출하면 덮어씁니다). **오늘 이전 날짜도 마찬가지** — [인증할 날짜]에서 예전 날짜를 고르면 그날 낸 내용이 그대로 불러와지고, 고쳐서 다시 제출하면 그 기록이 수정됩니다(원래 지각 여부는 최초 제출 시각 기준으로 유지됨) |
| 임시 저장 | 작성 중 창을 닫아도 내용이 남습니다 |
| 나의 진행 현황 | 인증/미인증/**면제**/연속 인증/인증률 + 날짜별 O·X·P 스트립 + **전체 인증 기록**(날짜 순, 접기). 면제(P)는 **미인증으로 세지 않아** 킥아웃 기준에 들어가지 않고, 인증률 계산에서도 빠집니다 |
| 전체 진행현황 | 이름을 선택하지 않아도 **모든 참여자**의 전일 인증률·전일 누락 · 지각 인원·킥아웃 위험 인원(누적 미인증 4회 이상 — 아직 킥아웃 대상은 아닌 사람도 포함)을 한눈에 볼 수 있는 대시보드. 앞의 두 지표는 **어제 24시 마감으로 확정된 기록** 기준이라 오늘 집계가 끝나지 않아 숫자가 요동치는 일이 없습니다(마감을 넘긴 지각 제출은 인증으로 치지 않고, 면제일인 사람은 인증률 분모에서 빠집니다). **전일 누락 · 지각 인원**·**킥아웃 위험 인원** 타일을 클릭하면 바로 아래에 해당하는 사람의 이름 목록이 펼쳐집니다 — 누락·지각은 **미제출 / 지각**으로 나눠서, 킥아웃 위험은 **이름 + 누적 미인증 횟수**를 누락 많은 순으로 보여주고 이미 킥아웃 대상인 사람은 붉은 톤으로 구분합니다. 참여자별 상세(인증/미인증/인증률/연속 인증) 표는 **접었다 펼 수 있고**, **이름순·이름 역순·인증률순**으로 정렬해서 볼 수 있습니다. |
| 인증 피드 | 각 글의 **인상 깊은 구절은 펼치지 않아도 바로 보이고**, **느낀 점**은 "느낀 점 보기"를 눌러야 펼쳐집니다. 기본은 [날짜별 보기]로, 화살표나 좌우 스와이프로 하루씩 넘겨보며 **추천 많은순 / 최신순**으로 정렬을 바꿀 수 있습니다. **전체 보기**를 누르면 지금까지의 모든 인증글을 **날짜별로 묶어** 모아 보는 전용 페이지(`feed-all.html`)가 새 창으로 열리고, **최신순 / 추천 많은순**으로 정렬을 바꿀 수 있습니다. 전체 보기의 카드는 한 줄에 최대 3장까지 놓고 **높이를 서로 맞춘 뒤 긴 글은 카드마다 따로 스크롤**하므로, 한 사람이 길게 썼다고 다른 카드가 비어 보이지 않습니다. 엄지척(👍)으로 서로 추천하고, 최다 득표자가 그날의 1등이 됩니다. 이미 누른 엄지척은 다시 눌러 **취소**할 수 있고, **본인 글은 추천할 수 없습니다**(참여 아이디를 선택한 상태에서만 적용, 날짜별 보기 기준). 각 글의 **텍스트 복사 버튼**을 누르면 작성자·날짜·내용이 클립보드에 텍스트로 복사되어, 카카오톡 등에 바로 붙여넣을 수 있습니다. **전체 보기**에서는 **사람을 골라서** 그 사람의 글만 모아 볼 수 있고, **TXT로 다운로드** 버튼으로 그 사람의 인증 기록 전체를 텍스트 파일로 내려받아 따로 보관할 수도 있습니다 — 각 기록에 **몇 일차**인지 표시되고, 전체 일정을 다 인증했다면 완주 축하 안내도 함께 담깁니다. |
| 명예의 전당 | **전일(어제)** 인증글을 엄지척(추천) 많이 받은 순으로 줄 세운 1~5위(동점은 공동 등수). 마감이 지나 추천이 더는 늘지 않는 어제 것을 확정된 기록으로 남깁니다 — 오늘 순위는 인증 피드에서 볼 수 있습니다. 마감을 넘긴 지각 글은 순위에서 제외합니다. **이름을 클릭하면** 그 사람의 인상 깊은 내용·느낀 점이 바로 아래에 펼쳐집니다. |

화면은 넓은 화면에서 **좌(인증 작성 · 나의 현황) / 우(명예의 전당 · 인증 피드) 2단**으로 배치되고,
900px 이하에서는 인증 → 피드 → 명예의 전당 순으로 한 줄로 쌓입니다.
피드와 최근 기록은 카드 안에서만 스크롤되어 페이지가 길어지지 않습니다.

챌린지 기간 밖(시작 전·종료 후)의 제출 허용 여부는 `js/config.js`의
`allowSubmitOutsidePeriod`로 정합니다. `true`(현재 값)이면 시연·연습용으로 제출할 수 있고,
`false`로 두면 기간 안에서만 제출됩니다. 어느 쪽이든 **기간 밖 기록은 집계(일일현황·인증률)에 반영되지 않습니다.**
화면 위에서부터 **책 소개 → 안내·챌린지 규칙 → 오늘/진행/마감 배너** 순서로 배치되어, 처음 들어온
참여자가 규칙부터 훑어본 뒤 바로 아래에서 오늘 진행 상황을 볼 수 있습니다. 배너의 **📖 오늘의 범위**를
누르면 그날 읽을 부분(회차별 안내, `js/config.js`의 `readingPlan`)이 펼쳐지고, **◀ ▶**로 다른 날짜의
범위도 넘겨 볼 수 있습니다 — 시작 전에는 1일차부터, 종료 후에는 마지막 회차부터 볼 수 있게 기본값이
맞춰집니다.

### `admin.html` — 운영진 대시보드

| 탭 | 기능 |
| --- | --- |
| **일일현황** | 참가자 × 날짜 매트릭스. 인증(O)·미인증(X)·면제(P)를 색으로 구분하고 누적 미인증이 많은 사람이 위로 정렬됩니다. 셀을 클릭하면 그날 제출 내용을 보고, 면제일을 바로 등록/해제할 수 있습니다. |
| **명단 관리** | 신청 폼으로 모은 이름을 줄바꿈/쉼표로 붙여넣어 일괄 등록. 이름·이메일·**전화번호**(문자 자동 발송용) 모두 표에서 바로 수정, **카톡방 참여 여부(미정/O/X) 드롭다운**으로 표시하고 **그 여부로 목록을 필터링**(미참여자만 보기 등)할 수 있습니다. **누적 미인증이 킥아웃 기준(6회)을 채운 사람**은 "아웃 처리" 대신 **"킥아웃 처리"** 버튼이 뜨는데, 누르면 그 순간부터 **그 이름으로는 인증을 제출할 수 없고** 명단·매트릭스에서 일반 아웃과 구분되는 **"킥아웃"** 배지가 붙습니다(그 외 사유로 참여를 중단시킬 때는 그대로 "아웃 처리"). "복귀"를 누르면 다시 참여 상태로 되돌릴 수 있습니다. 면제일 추가/삭제, 삭제도 가능합니다. **[알림 메일] 목록에서 이메일 채우기** 버튼으로 [알림 메일] 탭에 등록된 이름·메일 정보를 그대로 가져와 비어 있는 이메일 칸을 채울 수 있습니다. **"이름, 이메일" 두 열 또는 "이름, 이메일, 전화번호" 세 열이 있는 엑셀(.xlsx/.xls) 또는 CSV 파일을 업로드**하면 참여자 명단(인증 화면 드롭다운, 이메일·전화번호 칸 포함)과 [알림 메일] 탭의 수신자 목록에 한 번에 등록됩니다. |
| **공지문** | **단톡방 공지문**을 날짜별로 미리 써서 저장해 둘 수 있습니다(최소 30일치) — 저장하지 않은 날짜는 자동 생성된 초안이 대신 보이고, 자유롭게 고쳐서 저장할 수 있습니다. (예전에 스프레드시트가 매일 07:30/07:40에 보내던 **미인증 리포트** 생성 기능은, 이 앱의 [일일현황]·[전체 진행현황] 화면이 실시간으로 같은 정보를 보여주므로 제거했습니다.) |
| **제출 기록** | 날짜·참가자·검색어로 인증 내용을 조회합니다. 잘못 올라온 기록은 항목별 삭제 버튼으로 지울 수 있습니다. |
| **알림 메일** | 받는 사람 **이름·메일 주소**를 한 줄에 "이름, 메일주소" 형식으로 붙여넣어 한 번에 등록하거나 개별 삭제합니다(엑셀에서 두 열을 복사해 그대로 붙여넣기 가능). 목록은 [명단 관리]와 마찬가지로 이름 가나다순으로 정렬됩니다. 등록된 사람을 **이름으로 검색**하면 제목·본문을 자동으로 채워 주고, **[Gmail로 작성하기]**를 누르면 받는 사람·제목·본문이 채워진 **Gmail 새 작성창이 바로 열려**(별도 로그인·설정 없이, 브라우저에 로그인된 구글 계정 기준) 거기서 [보내기]만 누르면 되고, 다른 메일 앱을 쓴다면 **[복사하기]**로 클립보드에 담아 붙여넣어 보내도 됩니다. **미인증 경고 메일** 섹션에서는 현재 미인증 횟수가 있는 참여자 목록(현재 미인증 수 / 킥아웃 기준)을 보여주고, **[메일 작성]**을 누르면 몇 회 미인증됐는지와 누적 킥아웃 기준 횟수가 되면 킥아웃될 수 있다는 내용을 자동으로 채운 메일이 위 작성창에 채워집니다. **킥아웃 통보 메일** 섹션에서는 [명단 관리]에서 방금 **킥아웃 처리**한 사람 목록을 보여주고, **[메일 작성]**을 누르면 더 이상 이번 챌린지에 참여할 수 없다는 안내와 다음 챌린지 재신청 안내를 담은 메일이 채워집니다 — 여기까지는 모두 확인 후 Gmail로 작성하거나 복사해서 보내는 **수동 발송**입니다. 이와 별개로 **미인증 5회 자동 경고 메일** 섹션은 문구 편집·최근 발송 현황만 보여주는 화면이고, 실제 발송은 **Netlify 예약 함수가 매일 자정 직후 자동으로** 합니다(아래 "알림 메일" 섹션 참고). |
| **데이터** | 전체 백업(JSON) 내려받기/복원, 인증 기록 CSV, 일일현황 CSV, 전체 삭제. |

> 운영진 화면은 Firebase Authentication(구글 로그인)으로 막혀 있고, `js/config.js`의
> `adminEmails` 화이트리스트에 있는 계정만 대시보드를 볼 수 있습니다.
> 다만 이 검사는 **화면 표시만 막는 클라이언트 측 검사**입니다. 데이터 자체를 지키려면
> Firestore 보안 규칙에서 `participants` 쓰기 권한을 운영진 계정으로 제한해 두세요.

## 집계 규칙

| 표기 | 의미 | 미인증 카운트 |
| --- | --- | --- |
| `O` | 인증 완료 | 제외 |
| `X` | 미인증 (마감이 지난 날) | **포함** |
| `P` | 운영진이 등록한 면제일 | 제외 |
| `·` (연한 색) | 마감 전(오늘)·미래 날짜 | 제외 |
| `·` (더 연한 색) | 참여 기간 밖 (합류 전 / 아웃 이후) | 제외 |

- **오늘은 미인증으로 확정하지 않습니다.** 24시 마감 전이기 때문에, 미인증은 어제까지만 집계합니다.
- 날짜 판정은 기기 시간대와 무관하게 **Asia/Seoul 기준**입니다.
- 면제일에 **마감 전** 제출이 있으면 `O`로 인정합니다.
- 아웃 처리된 참가자는 아웃 날짜 다음 날부터 집계에서 빠지고, **그 이름으로는 인증 화면에서 더 이상
  제출할 수 없습니다**(킥아웃 처리든 일반 아웃 처리든 동일).
- 인증률 = 인증 ÷ (인증 + 미인증). 면제일은 분모에서 빠집니다.

### 지각 제출 처리 방식

참가자 화면에는 "인증할 날짜" 드롭다운이 있어, 자정 직후 등록해서 날짜가 하루 밀리는 문제 없이
**어떤 날짜로 제출할지 직접 고를 수 있습니다.** 다만 어떤 날짜를 고르든, **그 날짜 인증 기록이 처음
만들어진 시각(최초 제출 시각)이 그 날짜의 마감(24:00 KST)을 넘겼으면 계속 미인증(`X`)으로 집계**됩니다
— 기록 자체(인상 깊은 내용·느낀 점)는 남아서 인증 피드·제출 기록에서 볼 수 있지만, 인증률·킥아웃 판정에는
반영되지 않습니다. 지각으로 판정된 글에는 참가자 화면·운영진 화면 양쪽에 **"지각" 배지**가 함께 표시됩니다.

- 판정 기준은 **최초 제출 시각(`createdAt`)**입니다. 마감 전에 낸 인증을 나중에 오탈자만 고쳐도(재제출 시
  `updatedAt`만 갱신되고 `createdAt`은 유지) 여전히 `O`로 유지됩니다.
- 지각 제출이라도 그 날짜가 면제일로 등록돼 있으면 `P`로 처리됩니다.
- 판정 로직은 `js/utils.js`의 `isLate(date, createdAt)` / `statusFor()`에 있습니다.

## Firebase 전환 방법

저장 로직이 `CS.Store` 인터페이스 뒤에 숨어 있어, **화면 코드는 한 줄도 고치지 않고** 전환됩니다.

1. Firebase 콘솔에서 프로젝트 생성 → **Firestore Database** 활성화
2. 전환 전에 운영진 화면 → 데이터 탭 → **전체 백업(JSON) 내려받기**
3. `js/config.js`의 `CS.FIREBASE_CONFIG`에 웹 앱 설정값을 채우기
4. 같은 파일의 `backend`를 `'firebase'`로 변경
5. 다시 열어서 데이터 탭 → **복원하기**로 백업 JSON을 올리면 기존 기록이 그대로 이관됩니다

컬렉션 구조는 localStorage 스키마와 1:1로 대응합니다.

```
participants/{id}  { nickname, email, phone, kakaoJoined, status, joinDate, outDate, exemptDates[], note, createdAt }
submissions/{id}   { participantId, nickname, date, sentence, reflection,
                     upvotes, upvotedBy[], createdAt, updatedAt }
notifyEmails/{id}  { name, email, createdAt }   ← 야간 인증 알림 메일 수신자 목록
notices/{date}     { text, updatedAt }          ← 날짜별로 미리 써 두는 공지문 초안
meta/app           { ... }
```

권장 인덱스: `submissions(date)`, `submissions(participantId, date)`

> `js/store-firebase.js`는 위 인터페이스에 맞춰 작성해 두었지만, 실제 Firebase 프로젝트에 연결해
> 검증한 상태는 아닙니다. 전환할 때 보안 규칙(누가 읽고 쓸 수 있는지)을 함께 설정하세요.
>
> **컬렉션을 하나 늘렸다면(예: 이번에 추가된 `notices`) Firestore 보안 규칙에도 그 컬렉션의
> 읽기·쓰기를 허용하는 규칙이 있는지 꼭 확인하세요.** 규칙이 `participants`·`submissions`처럼
> 컬렉션 이름을 하나씩 나열해 허용하는 방식이라면, 새 컬렉션은 규칙을 추가하기 전까지
> 권한 오류로 막힙니다 — 이 경우 [알림 메일] 탭처럼 그 기능과 무관한 다른 탭까지 함께
> 먹통이 되지 않도록, 운영진 화면(`js/admin.js`)은 새 컬렉션을 읽어오는 부분만 따로
> try/catch로 감싸 실패해도 나머지 탭은 정상 동작하게 되어 있습니다.

## 알림 메일

대부분은 **운영진이 직접 보내는 수동 발송**이고, 딱 하나(누적 미인증 5회 경고)만 **Netlify 예약 함수로
자동 발송**됩니다.

### 수동 발송

앱이 받는 사람 목록 관리와 메일 제목·본문 자동 작성까지는 도와주고, 실제로 보내는 방법은 두 가지입니다.

- **[Gmail로 작성하기]**: 받는 사람·제목·본문이 채워진 **Gmail 새 작성창을 새 탭으로 바로 엽니다**
  (`https://mail.google.com/mail/?view=cm&...` 형태의 URL을 여는 것뿐이라, 별도 설정 없이 브라우저에
  로그인된 구글 계정 기준으로 뜹니다). 내용을 확인하고 그 Gmail 창에서 [보내기]만 누르면 됩니다 —
  이 앱이나 어떤 서버도 메일을 대신 보내지 않으므로 Google Cloud OAuth 클라이언트나 API 키 같은
  설정이 필요 없습니다.
- **[제목 + 본문 복사하기]**: 클립보드에 담아서, Gmail이 아닌 다른 메일 앱에 붙여넣어 보낼 때 씁니다.

운영진 화면의 **[알림 메일] 탭**에서:

1. 받는 사람 **이름·메일 주소**를 "이름, 메일주소" 형식으로 한 줄씩 등록합니다(엑셀 두 열을 그대로
   붙여넣기 가능). 참여 신청 시 받은 목록이 있다면 그대로 붙여넣으면 됩니다.
2. **이름으로 검색**해 대상을 고르면 제목·본문이 자동으로 채워집니다. 자유롭게 고친 뒤 위의 두 방법 중
   하나로 보내주세요.
3. **미인증 경고 메일** 목록에서는 현재 미인증 횟수가 있는 참여자별로 **[메일 작성]**을 누르면, 몇 회
   미인증됐는지와 누적 킥아웃 기준 횟수가 되면 킥아웃될 수 있다는 내용을 자동으로 채운 메일이 위
   작성창에 채워집니다 — 마찬가지로 확인 후 Gmail로 작성하거나 복사해서 보내면 됩니다.
4. **킥아웃 통보 메일** 목록에는 [명단 관리]에서 방금 **킥아웃 처리**한 참여자만 표시됩니다.
   **[메일 작성]**을 누르면 더 이상 이번 챌린지에 참여할 수 없다는 안내와 다음 챌린지 재신청 안내를
   담은 메일이 채워지니, 확인 후 Gmail로 작성하거나 복사해서 보내면 됩니다.

알림을 원하지 않는 참여자는 [알림 메일] 탭에서 목록에서 바로 삭제하면 됩니다.

**킥아웃 처리는 [명단 관리] 탭에서 합니다.** 누적 미인증이 킥아웃 기준(6회)에 닿은 참여자는 "아웃 처리"
버튼이 **"킥아웃 처리"**로 바뀌어 있습니다. 눌러서 확정하면 그 순간부터 **그 이름으로는 인증 화면에서
더 이상 제출할 수 없고**(이름 옆에 "(킥아웃)"이 붙고, 인증 버튼이 잠깁니다), [알림 메일] 탭의
**킥아웃 통보 메일** 목록에 나타납니다. 다음 기수에 다시 참여시키려면 "복귀" 버튼으로 되돌리면 됩니다.

### 자동 발송 — 미인증 5회 경고 메일·문자

누적 미인증이 정확히 **5회**(`CONFIG.autoWarnThreshold`, 킥아웃 기준 6회 바로 1회 전)가 된 참여자에게,
"1회만 더 미인증되면 킥아웃 대상이 될 수 있다"는 내용을 **정중한 어조로** 안내하는 메시지를 **Netlify
예약 함수가 매일 자정 직후(00:10 KST) 자동으로** 보냅니다(`netlify/functions/send-missed5-warning.js`).
**참여자에게 이메일 주소가 있으면 메일로, 전화번호가 있으면 문자(솔라피)로 — 둘 다 있으면 둘 다** 보내고,
메일·문자는 같은 문구를 씁니다. 같은 사람에게 중복으로 가지 않도록(두 채널 중 하나라도 성공하면) 참여자
문서에 발송 날짜를 기록해 두고(`복귀` 처리하면 초기화됨), 문구는 [알림 메일] 탭의 **"미인증 5회 자동
경고 메일"** 섹션에서 직접 고쳐 저장할 수 있습니다(킥아웃 통보 메일과 같은 방식 — `{{이름}}`·
`{{자동경고기준}}`·`{{킥아웃기준}}`·`{{앱주소}}` 자리표시자 지원). 같은 섹션에 마지막 자동 발송 실행
결과(채널별 발송 건수 등)도 표시되어, 실제로 잘 돌고 있는지 확인할 수 있습니다. 같은 섹션의 "지금 이미
5회인 사람" 목록에서 **[자동 발송 대상에서 제외]**를 누르면, 그 순간 이미 5회인 사람에게는(다른 방법으로
이미 안내했을 때) 보내지 않고 새로 5회가 되는 사람에게만 나가게 할 수 있습니다.

전화번호는 [명단 관리]에서 이메일과 마찬가지로 표에서 바로 입력·수정하거나, 명단 시트 업로드 시
**"이름, 이메일, 전화번호"** 세 열짜리 시트를 올리면 한 번에 채울 수 있습니다(두 열 "이름, 이메일"만
있는 시트도 그대로 지원합니다).

**필요한 설정 (Netlify 사이트 설정 → Environment variables):**

| 환경 변수 | 설명 |
| --- | --- |
| `FIREBASE_SERVICE_ACCOUNT_KEY` | Firebase 콘솔 → 프로젝트 설정 → 서비스 계정 → **"새 비공개 키 생성"**으로 받은 JSON 파일 내용을 그대로(한 줄로) 붙여넣습니다. 서버(Admin SDK) 권한으로 Firestore를 읽고 쓰기 위해 필요합니다 — 이게 없으면 이전에 겪었던 것과 같은 Firestore 429 오류가 날 수 있습니다. |
| `GMAIL_USER` | 발신용 지메일 주소. 예) `yourname@gmail.com` |
| `GMAIL_APP_PASSWORD` | 그 구글 계정의 **앱 비밀번호**(App Password) 16자리. 2단계 인증을 켠 뒤 https://myaccount.google.com/apppasswords 에서 발급받습니다. (일반 로그인 비밀번호는 SMTP 발송에 쓸 수 없습니다.) |
| `SOLAPI_API_KEY` | [솔라피](https://solapi.com) 콘솔 → [내 정보] → API Key 관리에서 발급받은 API Key. **전화번호가 등록된 참여자가 없다면 없어도 무방**합니다(메일만 나갑니다). |
| `SOLAPI_API_SECRET` | 같은 화면에서 함께 발급되는 API Secret. |
| `SOLAPI_SENDER` | 문자 발신번호. 솔라피에 **사전 등록(본인 인증)** 해 둔 번호여야 실제로 발송됩니다 — 통신법상 등록 안 된 번호로는 보낼 수 없습니다. |

값을 등록하고 재배포하면, `netlify.toml`의 `schedule` 설정을 Netlify가 자동으로 인식해 매일 자정 직후
실행합니다. Netlify 대시보드의 **Functions** 탭에서 `send-missed5-warning`이 예약 함수로 등록됐는지,
실행 로그가 정상인지 확인할 수 있습니다(무료 플랜에서도 예약 함수를 쓸 수 있습니다). 지메일 개인 계정은
하루 최대 약 500통까지 무료로 보낼 수 있어 메일 발송분은 이 정도 규모의 챌린지에 비용이 들지 않지만,
**솔라피 문자는 건당 요금이 있습니다**(장당 몇십 원 수준, 본문이 길어 LMS로 전환되면 SMS보다 비쌈).

## 알아 두면 좋은 제약

- **엄지척 중복 방지는 브라우저 단위입니다.** 로그인 없이 추천을 받기 위해 브라우저마다 만든
  임의 식별자(`clientId`)로 중복을 막습니다. 브라우저 데이터를 지우거나 다른 기기로 오면 다시 누를 수 있습니다.
  또한 참여 아이디를 선택한 상태에서는 **본인 글에 엄지척을 누를 수 없습니다** (여론 조작 방지).
- **피드 자동 갱신은 2분 간격**이며, 화면이 보이는 동안에만 동작합니다. 즉시 보려면 피드의 [↻ 새로고침]을 누르세요.
  (명예의 전당은 하루치만 읽으므로 함께 자동 갱신하고, 전체 진행현황은 전체 기록을 읽어야 해서 자동 갱신에서 제외했습니다 — Firestore 읽기 비용 절약)
- `backend: 'local'`로 되돌리면 데이터가 **브라우저 하나에만** 저장되어 참가자끼리 공유되지 않습니다.
  시연·점검용으로만 쓰고, 어느 모드든 데이터 탭에서 정기적으로 백업을 받아 두세요.
- 알림 메일은 **미인증 5회 자동 경고 메일 하나만 자동 발송**되고(위 "알림 메일" 섹션 참고, Netlify
  환경 변수 3개 설정이 끝나야 실제로 동작합니다), 나머지(특정 대상 안내·미인증 경고·킥아웃 통보)는
  [알림 메일] 탭에서 받는 사람 목록 관리와 제목·본문 자동 작성까지만 도와주고 실제 발송은 운영진이
  Gmail 작성창을 열거나 복사해서 직접 합니다.
- 인증 피드의 **[📋 텍스트 복사]** 버튼은 인증글(참여자 이름·인상 깊은 내용·느낀 점)을 클립보드에
  텍스트로 복사합니다. `navigator.clipboard`를 우선 쓰고, 이를 지원하지 않는 구형 브라우저·일부
  인앱 브라우저에서는 숨긴 `<textarea>` + `document.execCommand('copy')`로 대신합니다. 버튼 클릭
  (사용자 동작) 시점에 바로 실행되므로 카카오톡 인앱 브라우저를 포함한 대부분의 환경에서 안정적으로
  동작합니다.
  (처음엔 캔버스로 그린 이미지 카드를 다운로드하는 방식이었는데, 카카오톡 인앱 브라우저 등에서
  다운로드한 이미지가 파일·갤러리로 잘 이어지지 않는 문제가 반복됐고, 후기를 길게 남기는 참여자에게는
  이미지보다 텍스트가 더 유용하다는 의견이 있어 텍스트 복사로 바꿨습니다.)
- 명단 시트의 **엑셀(.xlsx/.xls) 업로드**는 [SheetJS](https://sheetjs.com)를 CDN에서 그때그때 불러와
  파싱합니다(버전 고정: xlsx@0.18.5). 인터넷 연결이 없거나 CDN이 막힌 환경에서는 안내 메시지가 뜨며,
  이 경우 CSV로 저장해서 올리면 별도 라이브러리 없이 바로 등록됩니다.
