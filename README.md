# 커밍쏜 독서챌린지 · 프로세스 이코노미 인증 시스템

구글폼 + 스프레드시트로 운영하던 인증 프로세스를 웹앱으로 옮긴 버전입니다.
빌드 도구 없이 HTML/CSS/JS 파일만으로 동작하며, **현재는 브라우저 localStorage에 저장**하고
나중에 설정 한 줄만 바꿔 **Firebase(Firestore)로 전환**할 수 있도록 저장소를 분리해 두었습니다.

- 챌린지 기간 : 2026년 8월 24일(월) ~ 9월 20일(일), 4주 (28일)
- OT : 2026년 8월 23일(일) 오전 10시
- 마감 : 매일 24시 정각, 유예 없음
- 킥아웃 : 누적 미인증 5회

---

## 실행 방법

정적 사이트라 서버가 없어도 `index.html`을 브라우저로 열면 동작합니다.
다만 파일 경로(`file://`)에서는 클립보드 복사 등 일부 기능이 제한되므로 로컬 서버 사용을 권합니다.

```bash
npx http-server -p 8080 -c-1
# → http://127.0.0.1:8080
```

GitHub Pages에 올리면 그대로 배포됩니다. (Settings → Pages → 브랜치 지정)

## 화면 구성

### `index.html` — 참가자 인증 화면

| 기능 | 설명 |
| --- | --- |
| 참여 아이디 | 명단에 등록된 닉네임을 **드롭다운에서 선택** (직접 입력하지 않아 오타로 인한 집계 누락이 없음) |
| 인증 3항목 | 오늘 읽은 챕터 / 가장 좋았던 문장 / 느낀 점 |
| 마감 카운트다운 | 24시까지 남은 시간을 실시간 표시 |
| 같은 날 재제출 | 새 인증이 쌓이지 않고 **기존 인증을 수정**합니다 |
| 임시 저장 | 작성 중 창을 닫아도 내용이 남습니다 |
| 나의 진행 현황 | 인증/미인증/면제/연속 인증/인증률 + 날짜별 O·X·P 스트립 + 최근 기록 5건 |

챌린지 기간 밖(시작 전·종료 후)에는 집계에 반영되지 않는 데이터가 쌓이지 않도록 제출이 잠깁니다.

### `admin.html` — 운영진 대시보드

| 탭 | 기능 |
| --- | --- |
| **일일현황** | 참가자 × 날짜 매트릭스. 인증(O)·미인증(X)·면제(P)를 색으로 구분하고 누적 미인증이 많은 사람이 위로 정렬됩니다. 셀을 클릭하면 그날 제출 내용을 보고, 면제일을 바로 등록/해제할 수 있습니다. |
| **명단 관리** | 신청 폼으로 모은 닉네임을 줄바꿈/쉼표로 붙여넣어 일괄 등록. 닉네임 수정, 아웃 처리·복귀, 면제일 추가/삭제, 삭제. |
| **리포트 · 공지문** | 스프레드시트가 매일 07:30/07:40에 보내던 **미인증 리포트**와 **단톡방 공지문 초안**을 생성하고 클립보드로 복사합니다. |
| **제출 기록** | 날짜·참가자·검색어로 인증 내용을 조회합니다. |
| **데이터** | 전체 백업(JSON) 내려받기/복원, 인증 기록 CSV, 일일현황 CSV, 전체 삭제. |

> 운영진 화면은 로그인이 없습니다. 정적 사이트에서 클라이언트 측 비밀번호는 실질적인 보안이 되지 않기 때문에
> 넣지 않았습니다. 공개 배포 시에는 링크를 공유하지 않거나, Firebase 전환 후 Firebase Authentication으로
> 접근을 제한하세요.

## 집계 규칙

| 표기 | 의미 | 미인증 카운트 |
| --- | --- | --- |
| `O` | 인증 완료 | 제외 |
| `X` | 미인증 (마감이 지난 날) | **포함** |
| `P` | 운영진이 등록한 면제일 | 제외 |
| `·` (연한 색) | 마감 전(오늘)·미래 날짜 | 제외 |
| `·` (더 연한 색) | 참여 기간 밖 (합류 전 / 아웃 이후) | 제외 |

- **오늘은 미인증으로 확정하지 않습니다.** 24시 마감 전이기 때문에, 미인증은 어제까지만 집계합니다.
- 날짜 판정은 기기 시간대와 무관하게 **Asia/Seoul 기준**입니다.
- 면제일에 실제 제출이 있으면 `O`로 인정합니다.
- 아웃 처리된 참가자는 아웃 날짜 다음 날부터 집계에서 빠집니다.
- 인증률 = 인증 ÷ (인증 + 미인증). 면제일은 분모에서 빠집니다.

### 설정 바꾸기

기간이나 기준을 바꿀 때는 `js/config.js`만 수정하면 모든 화면에 반영됩니다.

```js
startDate: '2026-08-24',   // 시작일
endDate:   '2026-09-20',   // 종료일
kickoutThreshold: 5,       // 누적 미인증 N회 → 킥아웃
timezone: 'Asia/Seoul',    // 마감 판정 기준
```

## Firebase 전환 방법

저장 로직이 `CS.Store` 인터페이스 뒤에 숨어 있어, **화면 코드는 한 줄도 고치지 않고** 전환됩니다.

1. Firebase 콘솔에서 프로젝트 생성 → **Firestore Database** 활성화
2. 전환 전에 운영진 화면 → 데이터 탭 → **전체 백업(JSON) 내려받기**
3. `js/config.js`의 `CS.FIREBASE_CONFIG`에 웹 앱 설정값을 채우기
4. 같은 파일의 `backend`를 `'firebase'`로 변경
5. 다시 열어서 데이터 탭 → **복원하기**로 백업 JSON을 올리면 기존 기록이 그대로 이관됩니다

컬렉션 구조는 localStorage 스키마와 1:1로 대응합니다.

```
participants/{id}  { nickname, status, joinDate, outDate, exemptDates[], note, createdAt }
submissions/{id}   { participantId, nickname, date, chapter, sentence, reflection, createdAt, updatedAt }
meta/app           { ... }
```

권장 인덱스: `submissions(date)`, `submissions(participantId, date)`

> `js/store-firebase.js`는 위 인터페이스에 맞춰 작성해 두었지만, 실제 Firebase 프로젝트에 연결해
> 검증한 상태는 아닙니다. 전환할 때 보안 규칙(누가 읽고 쓸 수 있는지)을 함께 설정하세요.

## 테스트

```bash
node test/logic.test.js            # 날짜·집계·저장소 로직 (Node만 있으면 됨)

npx http-server -p 8765 -c-1 &     # UI 테스트는 로컬 서버 필요
node test/ui.test.js               # playwright 필요
```

UI 테스트는 실행일이 챌린지 기간 한가운데가 되도록 `js/config.js` 응답만 가로채 날짜를 바꾸고,
나머지는 실제 코드를 그대로 검증합니다.

## 현재 저장 방식의 한계

localStorage는 **브라우저 하나에만** 저장됩니다.

- 참가자가 각자 자기 기기에서 인증하면 운영진 화면에서는 보이지 않습니다.
- 지금 구조는 한 대의 기기(운영진 PC 또는 공용 화면)에서 함께 쓰거나, 시스템 점검·시연 용도에 맞습니다.
- 실제로 참가자들이 각자 제출하게 하려면 **Firebase 전환이 필요합니다.**
- 브라우저 데이터를 지우면 기록이 사라지므로, 그 전까지는 데이터 탭에서 정기적으로 백업을 받아 두세요.
