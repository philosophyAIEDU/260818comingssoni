# 퍼스널메이커스 독서 챌린지 · 프로세스 이코노미 인증 시스템

구글폼 + 스프레드시트로 운영하던 인증 프로세스를 웹앱으로 옮긴 버전입니다.
빌드 도구 없이 HTML/CSS/JS 파일만으로 동작하며, **현재는 Firebase(Firestore)에 저장**합니다.
저장소가 인터페이스 뒤에 분리되어 있어 `js/config.js`의 `backend` 한 줄로
브라우저 localStorage 모드로 되돌릴 수도 있습니다. (오프라인 시연·테스트용)

- 챌린지 기간 : 2026년 8월 24일(월) ~ 9월 20일(일), 4주 (28일)
- OT : 2026년 8월 23일(일) 오전 10시
- 마감 : 매일 24시 정각, 유예 없음
- 킥아웃 : 누적 미인증 5회 (개인 사정으로 인증이 어려운 날엔 최소 3주일 전 운영진께 면제 요청)

---

## 실행 방법

정적 사이트라 서버가 없어도 `index.html`을 브라우저로 열면 동작합니다.
다만 파일 경로(`file://`)에서는 클립보드 복사 등 일부 기능이 제한되므로 로컬 서버 사용을 권합니다.

```bash
npx http-server -p 8080 -c-1
# → http://127.0.0.1:8080
```

Netlify(현재 배포 주소: https://comingssoni.netlify.app/)나 GitHub Pages에 올리면 그대로 배포됩니다.

## 화면 구성

### `index.html` — 참가자 인증 화면

| 기능 | 설명 |
| --- | --- |
| 참여 아이디 | 명단에 등록된 이름(실명)을 **드롭다운에서 선택** (직접 입력하지 않아 오타로 인한 집계 누락이 없음) |
| 인증할 날짜 | 기본값은 오늘이지만, **드롭다운으로 다른 날짜를 골라 제출**할 수 있습니다. 자정 직후 제출로 날짜가 하루 밀려서 전날 기록이 다음날 것과 뒤섞이거나 덮어써지는 문제를 막기 위한 기능입니다 — 다만 마감을 넘긴 날짜로 제출해도 **미인증(X)으로 계속 집계**됩니다 (아래 [지각 제출 처리 방식](#지각-제출-처리-방식) 참고). |
| 인증 2항목 | 오늘 읽은 챕터에서 가장 인상 깊었던 핵심 내용 / 오늘 책을 읽고 느낀 점(적용할 점) — 입력을 최소화하기 위해 챕터 입력란은 없앴습니다 |
| 마감 카운트다운 | 24시까지 남은 시간을 실시간 표시 |
| 같은 날짜 재제출 | 새 인증이 쌓이지 않고 **기존 인증을 수정**합니다 (별도의 삭제 버튼은 없고, 다시 작성해 제출하면 덮어씁니다) |
| 임시 저장 | 작성 중 창을 닫아도 내용이 남습니다 |
| 나의 진행 현황 | 인증/미인증/면제/연속 인증/인증률 + 날짜별 O·X·P 스트립 + 최근 기록 5건(접기) |
| 전체 진행현황 | 이름을 선택하지 않아도 **모든 참여자**의 오늘 인증률·참여 인원·킥아웃 위험 인원(누적 미인증 3~4회)과, 참여자별 인증/미인증/인증률/연속 인증을 한 번에 볼 수 있는 대시보드 |
| 인증 피드 | 헤더의 [날짜별 보기]/[전체 보기] 탭으로 전환합니다. 날짜별 보기는 하루씩 넘겨보고, 전체 보기는 지금까지의 인증글을 최신순으로 한 번에 봅니다. 엄지척(👍)으로 서로 추천하고, 최다 득표자가 그날의 1등이 됩니다. 이미 누른 엄지척은 다시 눌러 **취소**할 수 있고, **본인 글은 추천할 수 없습니다.** |
| 명예의 전당 | 날짜별 1등 누적 횟수 Top 5 |

화면은 넓은 화면에서 **좌(인증 작성 · 나의 현황) / 우(명예의 전당 · 인증 피드) 2단**으로 배치되고,
900px 이하에서는 인증 → 피드 → 명예의 전당 순으로 한 줄로 쌓입니다.
피드와 최근 기록은 카드 안에서만 스크롤되어 페이지가 길어지지 않습니다.

챌린지 기간 밖(시작 전·종료 후)의 제출 허용 여부는 `js/config.js`의
`allowSubmitOutsidePeriod`로 정합니다. `true`(현재 값)이면 시연·연습용으로 제출할 수 있고,
`false`로 두면 기간 안에서만 제출됩니다. 어느 쪽이든 **기간 밖 기록은 집계(일일현황·인증률)에 반영되지 않습니다.**
챌린지 시작 전에는 D-day와 OT 안내, "지금 올리는 인증은 연습용" 문구가 **책 소개 카드 안(제목·저자 바로 아래)**에 표시되어,
처음 들어온 참여자도 헷갈리지 않도록 눈에 잘 띄는 위치에 둡니다.

> Firestore 보안 규칙에서 `participants` 쓰기 권한을 운영진 계정으로 제한해 두세요.

## 집계 규칙

| 표기 | 의미 | 미인증 카운트 |
| --- | --- | --- |
| `O` | 인증 완료 | 제외 |
| `X` | 미인증 (마감이 지난 날) | **포함** |
| `P` | 운영진이 등록한 면제일 | 제외 |
| `·` (연한 색) | 마감 전(오늘)·미래 날짜 | 제외 |
| `·` (더 연한 색) | 참여 기간 밖 (합류 전 / 아웃 이후) | 제외 |

- **오늘은 미인증으로 확정하지 않습니다.** 24시 마감 전이기 때문에, 미인증은 어제까지만 집계합니다.
- 날짜 판정은 기기 시간대와 무관하게 **Asia/Seoul 기준**입니다.
- 면제일에 **마감 전** 제출이 있으면 `O`로 인정합니다.
- 아웃 처리된 참가자는 아웃 날짜 다음 날부터 집계에서 빠집니다.
- 인증률 = 인증 ÷ (인증 + 미인증). 면제일은 분모에서 빠집니다.

### 지각 제출 처리 방식

참가자 화면에는 "인증할 날짜" 드롭다운이 있어, 자정 직후 등록해서 날짜가 하루 밀리는 문제 없이
**어떤 날짜로 제출할지 직접 고를 수 있습니다.** 다만 어떤 날짜를 고르든, **그 날짜 인증 기록이 처음
만들어진 시각(최초 제출 시각)이 그 날짜의 마감(24:00 KST)을 넘겼으면 계속 미인증(`X`)으로 집계**됩니다
— 기록 자체(인상 깊은 내용·느낀 점)는 남아서 인증 피드·제출 기록에서 볼 수 있지만, 인증률·킥아웃 판정에는
반영되지 않습니다. 지각으로 판정된 글에는 참가자 화면·운영진 화면 양쪽에 **"지각" 배지**가 함께 표시됩니다.

- 판정 기준은 **최초 제출 시각(`createdAt`)**입니다. 마감 전에 낸 인증을 나중에 오탈자만 고쳐도(재제출 시
  `updatedAt`만 갱신되고 `createdAt`은 유지) 여전히 `O`로 유지됩니다.
- 지각 제출이라도 그 날짜가 면제일로 등록돼 있으면 `P`로 처리됩니다.
- 판정 로직은 `js/utils.js`의 `isLate(date, createdAt)` / `statusFor()`에 있습니다.

### 설정 바꾸기

기간이나 기준을 바꿀 때는 `js/config.js`만 수정하면 모든 화면에 반영됩니다.

```js
title: '퍼스널메이커스 독서 챌린지', // 좌측 상단 브랜드명

adminEmails: [...],        // 운영진 구글 계정 화이트리스트
```

## Firebase 전환 방법

저장 로직이 `CS.Store` 인터페이스 뒤에 숨어 있어, **화면 코드는 한 줄도 고치지 않고** 전환됩니다.

1. Firebase 콘솔에서 프로젝트 생성 → **Firestore Database** 활성화
2. 전환 전에 운영진 화면 → 데이터 탭 → **전체 백업(JSON) 내려받기**
3. `js/config.js`의 `CS.FIREBASE_CONFIG`에 웹 앱 설정값을 채우기
4. 같은 파일의 `backend`를 `'firebase'`로 변경
5. 다시 열어서 데이터 탭 → **복원하기**로 백업 JSON을 올리면 기존 기록이 그대로 이관됩니다

컬렉션 구조는 localStorage 스키마와 1:1로 대응합니다.

```
participants/{id}  { nickname, status, joinDate, outDate, exemptDates[], note, createdAt }
submissions/{id}   { participantId, nickname, date, sentence, reflection,
                     upvotes, upvotedBy[], createdAt, updatedAt }
notifyEmails/{id}  { name, email, createdAt }   ← 야간 인증 알림 메일 수신자 목록
meta/app           { ... }
```

권장 인덱스: `submissions(date)`, `submissions(participantId, date)`

> `js/store-firebase.js`는 위 인터페이스에 맞춰 작성해 두었지만, 실제 Firebase 프로젝트에 연결해
> 검증한 상태는 아닙니다. 전환할 때 보안 규칙(누가 읽고 쓸 수 있는지)을 함께 설정하세요.

## 야간 인증 알림 메일 설정

운영진 화면의 **[알림 메일] 탭**에서 수신자 이름·메일 주소를 추가/삭제할 수 있고,
실제 발송은 Netlify **예약 함수(Scheduled Function)**가 매일 밤 22시(KST)에 자동으로 실행합니다.

```
netlify/functions/send-daily-reminder.js       매일 밤 22시 자동 실행 (netlify.toml 의 schedule)
netlify/functions/send-daily-reminder-test.js  운영진 화면의 [지금 테스트 발송] 버튼이 호출
netlify/functions/_lib/notify.js               공통 로직 (수신자 조회 + 메일 발송)
```

**비용 없이 지메일 SMTP로 발송**하도록 구현했습니다 (`nodemailer` 사용). 아래 순서로 준비하세요.

1. 발송용으로 쓸 구글 계정에서 **2단계 인증**을 켭니다. (계정 설정 → 보안 → 2단계 인증)
2. https://myaccount.google.com/apppasswords 에서 **앱 비밀번호**를 발급받습니다. (16자리, 공백 없이)
3. **Netlify 사이트 설정 → Environment variables**에 아래 값을 등록합니다.

| 변수 | 설명 |
| --- | --- |
| `GMAIL_USER` | 발송용 지메일 주소. 예) `personalmakers.reading@gmail.com` |
| `GMAIL_APP_PASSWORD` | 1~2번에서 발급받은 앱 비밀번호 16자리 (일반 로그인 비밀번호 아님) |

지메일 개인 계정은 **하루 약 500통까지 무료**로 보낼 수 있어, 이 정도 규모의 챌린지에는 별도 비용이 들지 않습니다.
수신자마다 **이름이 들어간 개인화된 메일을 한 통씩** 따로 발송합니다(같은 메일을 여럿에게 뿌리는 게 아니라
`안녕하세요, {{NAME}}님!`처럼 받는 사람 이름이 실제로 치환되어 나갑니다). 메일 본문에는 인증 앱 주소
(`https://comingssoni.netlify.app/`)와 오늘 밤 24시 마감 안내가 포함됩니다.

수신자 이름은 운영진이 [알림 메일] 탭에서 "이름, 메일주소" 형식으로 직접 등록합니다 — 참여 신청 시 받은
이름·메일 목록(엑셀 등)이 있다면 두 열을 그대로 복사해 붙여넣으면 한 번에 등록됩니다. 이름 없이 메일
주소만 등록된 경우에는 "참여자님"으로 표시됩니다.

> 다른 메일 발송 방식(회사 도메인 메일, Resend 등 유료 서비스)으로 바꾸고 싶다면
> `netlify/functions/_lib/notify.js`의 `sendViaGmail` 함수만 교체하면 됩니다.

> `send-daily-reminder.js`는 Firestore의 `notifyEmails` 컬렉션을 **REST API로 인증 없이** 조회합니다.
> 이 프로젝트의 다른 컬렉션(참가자·제출 기록)도 클라이언트에서 로그인 없이 읽고 쓰는 구조이므로 동일하게 열어 둔
> 것이지만, 더 엄격하게 막고 싶다면 서비스 계정을 이용한 Firebase Admin SDK 방식으로 바꾸고
> `notifyEmails` 컬렉션의 Firestore 보안 규칙에서 서버(Admin) 읽기만 허용하도록 조정하세요.
>
> 알림을 원하지 않는 참여자는 운영진에게 요청하면 [알림 메일] 탭에서 목록에서 바로 삭제할 수 있습니다.

## 알아 두면 좋은 제약

- **엄지척 중복 방지는 브라우저 단위입니다.** 로그인 없이 추천을 받기 위해 브라우저마다 만든
  임의 식별자(`clientId`)로 중복을 막습니다. 브라우저 데이터를 지우거나 다른 기기로 오면 다시 누를 수 있습니다.
  또한 참여 아이디를 선택한 상태에서는 **본인 글에 엄지척을 누를 수 없습니다** (여론 조작 방지).
- **피드 자동 갱신은 2분 간격**이며, 화면이 보이는 동안에만 동작합니다. 즉시 보려면 피드의 [↻ 새로고침]을 누르세요.
  (명예의 전당·전체 진행현황은 전체 기록을 읽어야 해서 자동 갱신에서 제외했습니다 — Firestore 읽기 비용 절약)
- `backend: 'local'`로 되돌리면 데이터가 **브라우저 하나에만** 저장되어 참가자끼리 공유되지 않습니다.
  시연·점검용으로만 쓰고, 어느 모드든 데이터 탭에서 정기적으로 백업을 받아 두세요.
- 야간 알림 메일은 Netlify 예약 함수 + 환경 변수 설정이 끝나야 실제로 발송됩니다. 설정 전에는
  [알림 메일] 탭에서 수신자 목록 관리와 메일 미리보기만 가능합니다.
