# 라이브 대본 → 인사이트 정리본

시즌이 끝나면 라이브 4번을 한 편으로 묶어 **선물**로 보낸다. 받는 사람은 이미 책을 다 읽고 라이브를
들은 멤버다. 그러니 책 요약이 아니라 **"커밍쏜이 이 책에서 무엇을 가져갔는가"** 를 남긴다.

## 받는 것

- 라이브 대본 **4개** (녹화 자막이든, 유튜브 스크립트든, 메모든). 파일이면 `transcripts/` 아래에 두고
  작업한다 — 이 폴더는 gitignore 되어 있고, **개인 발언이 들어 있으니 절대 커밋하지 않는다.**
- 시즌 정보는 `js/config.js`의 해당 시즌에서 읽는다(책 이름·저자·라이브 날짜·일수). 묻지 않는다.
- 대본이 3개 이하이거나 하나가 비어 있으면, **있는 것만으로 쓰되 첫 줄에 그 사실을 적고** 사용자에게 알린다.
- 유튜브 링크만 오면: 클라우드 세션에서는 YouTube가 IP를 막아 yt-dlp·자막 API·외부 자막 사이트가 모두 실패했다(2026-10).
  오래 붙잡지 말고 바로 **YouTube Studio 자막 다운로드나 [스크립트 표시] 복사로 붙여넣기**를 부탁한다.
  붙여넣은 대본은 다시 받아 적지 말고 세션 기록에서 그대로 뽑아 `transcripts/live{N}.txt`로 저장한다. 링크 순서와 회차가
  뒤바뀐 적이 있으니 **영상 제목(oEmbed)으로 회차를 확인**한다.

## 쓰는 순서

### 1. 대본 넷을 각각 먼저 훑는다 — 종합은 그다음

대본 하나마다 아래를 뽑아 `transcripts/_메모.md`에 적는다(이 파일도 커밋하지 않는다).

- 그 라이브의 핵심 주장 1~2개
- 커밍쏜이 **자기 경험**으로 말한 장면 (언제·어디서·무슨 일이 있었고 뭐라고 생각했는지)
- 책에서 직접 인용한 문장 (있는 그대로, 쪽수가 나오면 같이)
- 구체적 숫자 (구독자, 매출, 년수, 횟수)
- 멤버 질문에 답한 부분 — 여기서 제일 좋은 문장이 자주 나온다

**빼는 것** (정리본에 절대 들어가지 않는다):
- 일정·공지: "다음 주", "월요일까지", "발제문 올릴게요", "인증 마감", "다음 시즌 책은"
- 결제·모집·해지, 상품 홍보, 다른 강의 이야기 (단, 페이지 **맨 아래 상품 안내 한 블록**은 예외 — 3-2)
- 그날의 근황·이동·컨디션 ("지금 시드니인데", "어제 잠을 못 자서") — 뉴스레터 도입부에는 쓰지만 정리본에는 안 쓴다
- 특정 멤버 실명. 사례로 쓰려면 "한 멤버분이"로 익명화한다
- 자동 자막의 오타로 애매한 인명·용어 — 원리만 남기고 이름은 뺀다

### 2. 꼭지를 고른다 — 5개 이상 10개 이하

- 라이브 하나에서 보통 2~3개가 나온다. **네 라이브를 가로지르는 주제는 하나로 합친다**(같은 말을 두 번 하지 않는다).
- 순서는 라이브 순서가 아니라 **"왜 → 무엇 → 어떻게"** 순서. 마음가짐 → 원리 → 실행.
- 한 줄 주장으로 못 쓰는 꼭지는 버린다. 제목만 읽어도 뜻이 통해야 한다.
- 꼭지 목록을 사용자에게 먼저 보여 주고 확인받은 뒤 본문을 쓴다. (대본을 다시 읽는 비용이 크다 —
  방향이 틀리면 여기서 잡는다.)

- 따로 말이 없으면 **5꼭지 · 전자책 10페이지 내외**로 잡는다(『꿈과 돈』 때 커밍쏜이 정한 형식이고, 설계는 그대로 통과했다).

### 3. `tools/templates/인사이트정리본.md` 뼈대대로 쓴다

각 꼭지는 **훅 → 못났던 과거의 나 → 원리 → 기억할 한 가지 → 이렇게 적용해 보세요 → 👉 내게 적용** 순서다.
5꼭지 기준 꼭지당 1,600~2,200자, 전체(마크다운 제외, 공백 포함) 10,000~12,500자. 꼭지가 늘면 꼭지당 분량을 줄인다.
독자는 1인기업·크리에이터다 — 꼭지마다 "그래서 내 콘텐츠·브랜딩·비즈니스에선 어떻게?"에 답해야 한다.

#### 3-1. 맥락과 결 — 커밍쏜이 직접 고친 것에서 배운 규칙

『꿈과 돈』 정리본을 커밍쏜이 고쳐서 게시했다. 무엇을 왜 고쳤는지는
`references/s2-꿈과돈-수정에서-배운-것.md`에 있다. 초안은 `references/s2-꿈과돈-초안.md`, 최종본은 `archive/s2-꿈과돈/인사이트정리본.*.md` 중 가장 최근 날짜 사본(지금은 `.2026-10-21_0917.md`)이고, **쓰기 전에 최종본을 한 번 읽는다.** 요점은 두 가지다.

**결이 다른 내용은 넣지 않는다**
- 꼭지 제목의 주장을 돕지 않는 문단은 좋은 일화여도 뺀다. 다른 꼭지로 옮기거나 버린다.
  예: '실력의 늪' 꼭지의 에어비앤비 프라이팬(감동 서비스 이야기), '상품·콘텐츠 설계' 꼭지의 커뮤니티 단락.
- 라이브에서 나온 좋은 이야기를 전부 담으려 하지 않는다. 남는 건 메모에만 둔다.
- 실행법은 **2~3개.** 개수를 채우려고 억지로 만들지 않는다.
- 본문을 덜어 냈으면 제목·목차·3줄 요약에 그 내용이 남아 있지 않은지 다시 맞춘다.

**맥락을 한 겹 더 깐다** — 처음 읽는 사람도 한 번에 따라오게
- 프로그램·고유명사는 첫 등장 때 한 줄로 설명한다. 예: "코호트 기반 코칭 프로그램인 팀 퍼스널메이커스".
- 경험에는 배경(언제·어디서·얼마나)을 붙인다. 예: "1년간 디지털 노마드로 살면서 해외에서".
- 공식·정의는 주어부터 쓴다. "인지도 빼기 보급도"가 아니라 "럭셔리는 인지도 - 보급도이다".
- 사례 뒤에는 '그래서 왜 그런지'를 한 문장으로 붙인다. 용어(호혜의 법칙 등) 뒤에는 '그래서 무슨 일이 생기는지'를 붙인다.
- 원리 끝에는 "기억해야 하는 포인트는 1가지입니다 / 기억하세요." 같은 정리 문단을 둔다.
  원리 문장 뒤에는 "우리는 ~해야 합니다" 같은 행동 문장을 붙인다.
- 앞 꼭지에서 다룬 개념이 다시 나오면 "기억나시죠? …"로 다시 불러 이어 준다.
- 짝 개념(기능 = 문제 해결, 의미 = 라이프스타일)은 매번 같이 묶어 말한다.
- 같은 개념은 한 낱말로 통일한다. 커밍쏜은 'DB'를 쓴다(본문에서 '메일 주소'와 섞어 쓰지 않는다). '상품'은 늘 '상품과 서비스'로 말한다.

**목소리**
- 핵심 원리는 멤버 발언으로 돌리지 않고 커밍쏜 목소리로 말한다("한 멤버분이 정답을 주셨죠" ✕).
- 과거의 나는 단정하지 말고 사실 범위 안에서 쓴다. "기능을 팔았어요" 대신 "기능을 파는데 집중했던 적이 있었어요".
- 독자 속마음을 대신 묻는 반문을 쓴다("쪽팔린다고요? 짜친다고요?").
- 실행법은 기계적 지시보다 스스로 다시 묻게 한다. 대본에 없는 구체적 지시(어디에 올려라 등)는 만들지 않는다.
- 👉 내게 적용에는 태도까지 붙인다("…넣으며 당당하게 드러내본다").
- 마무리는 퍼메스 독서멤버십을 이름으로 부르고, "계속해서 같이 가보시죠"처럼 함께 가자는 말로 끝낸다. 그다음이 서명이다.
  일정·결제 같은 운영 이야기는 여전히 넣지 않는다.

말투(커밍쏜 뉴스레터 그대로):
- ~입니다/~요 존댓말. 편안하지만 가볍지 않게. "~거든요", "~잖아요", "~더라고요"를 자연스럽게 섞는다.
- **1인칭.** "저는", "제가". 라이브에서 한 말을 커밍쏜 시점으로 다시 쓴다. 3인칭 요약("커밍쏜은 ~라고 말했다")은 금지.
- 문장은 짧게. 한 문단은 1~3문장. 줄바꿈을 자주.
- 과거의 못났던 나를 솔직하게 (창피하지만, 참 못났죠?). 그때 속마음은 작은따옴표로 직접 인용.
- 수사적 질문 뒤 자문자답. 원리 앞에는 "이게 무슨 말이냐고요? 쉽게 예를 들어볼게요."
- 핵심 문장은 **굵게** — 꼭지당 1~3개, 단락의 결론 문장을 통째로(구조용 '이렇게 적용해 보세요'·'👉'는 따로 센다). 밑줄·색은 노션에 올린 뒤 손으로 넣는다.
- 이탤릭은 쓰지 않는다(앱도 뉴스레터도 정체로 통일했다).
- 이모지는 뼈대에 있는 것(1️⃣ 👉 📚 🎙, 맨 아래 상품 안내의 📍)만.
- 마지막 줄은 서명: **"결국, 그렇게 내가 주인공이 되는 시간이 커밍쏜."**

#### 3-2. 맨 아래 상품 안내 한 블록

출처 줄(📚·🎙) 다음, 페이지 맨 끝에 커밍쏜의 상품 하나를 안내한다(『꿈과 돈』 때 커밍쏜이 직접 넣었다 —
`references/s2-꿈과돈-수정에서-배운-것.md` 마지막 절). 📍 + "~하고 싶으시다면" 한 문장 → 상품이 무엇인지(대본에 나온 사실만) →
"아래에서 신청하실 수 있습니다!" → 상품 페이지 링크(제목 그대로). 가격·마감·할인은 쓰지 않는다.
**어떤 상품·링크를 넣을지는 꼭지 확인 때 같이 묻는다** — 지난 시즌 링크를 재사용하거나 지어내지 않는다. 올리기 전에 링크가 열리는지,
페이지 제목이 맞는지 `curl -sSL` 로 확인한다.

### 4. 검증 — 하나라도 걸리면 고친 뒤 올린다

- [ ] 꼭지 수가 5~10개인가
- [ ] 모든 인용문·숫자·사례가 **대본에 실제로 있는가** (대본에 없는 건 지운다. 지어내지 않는다)
- [ ] 아래 낱말이 본문에 없는가: `다음 주` `공지` `마감` `결제` `해지` `모집` `다음 시즌` `신청` `인증해` — 있으면 그 문장은 일정·운영 이야기다 (맨 아래 상품 안내 블록의 "신청"은 예외)
- [ ] 멤버 실명이 없는가
- [ ] 각 꼭지에 **👉 내게 적용** 한 줄이 있는가
- [ ] 3줄 요약·목차·꼭지 제목이 본문과 맞는가 (본문을 고쳤으면 셋 다. 예: 완료주의 단락을 뺐는데 제목에 "완벽 대신 완료로"가 남았던 일 → "실력을 쌓으면서 동시에 파세요")
- [ ] 같은 개념을 다른 낱말로 섞어 쓰지 않았는가 (DB / 메일 주소)
- [ ] **결 검사**: 꼭지마다 문단을 하나씩 짚으며 "이 문단이 제목의 주장을 돕는가?" — 아니면 뺀다. 실행법도 같은 질문으로
- [ ] **맥락 검사**: 처음 나오는 프로그램·용어마다 한 줄 설명이 있는가, 사례·용어 뒤에 '그래서 왜/무슨 일'이 있는가
- [ ] 맨 아래 상품 안내 블록이 있고, 🎙 출처 줄과 그 블록 사이에 구분선(---)이 있으며, 링크가 열리고 제목이 맞는가
- [ ] 띄어쓰기·맞춤법 한 번 훑기 (지난번 남은 예: 파는데 집중 → 파는 데, 신호에요 → 신호예요, 가치있는·관심있는 → 가치 있는·관심 있는, 다시한번 → 다시 한번, 응원하게될 → 응원하게 될, 두문장 → 두 문장, 같이가보시죠 → 같이 가보시죠, 서비스를 하나를 → 서비스 하나를)
- [ ] 마크다운을 뺀 글자 수가 4,000자 이상인가 (`node -e` 로 센다)

### 5. 노션에 올린다

- 부모: 「퍼메스 독서챌린지」 `3c2f15a6c51c80108cb1c88b5212be7d`
- 제목: `『{책이름}』 인사이트 정리본 — 커밍쏜 독서 라이브 {N}회 총정리`, 아이콘 `🎁`
- `notion-create-pages` 로 한 번에 올린다. HTML 주석(`<!-- -->`)과 `(…)` 안내문은 빼고 올린다.
- 올린 뒤 `notion-fetch` 로 다시 읽어 번호가 밀리지 않았는지, 굵게가 살아 있는지 본다.
- 페이지는 **비공개로 두고** 링크만 사용자에게 준다. 멤버에게 보내는 건 사용자가 한다
  (운영진 화면 [알림 메일 › 🎁 선물 대상자] 에서 명단·이메일을 복사할 수 있다).

## 커밍쏜이 최종본을 고친 뒤

- 게시본은 **고치지 않는다.** 웹에 게시되면 `node tools/notion-snapshot.mjs <페이지ID> archive/<시즌id>-<책>/인사이트정리본.md`로 떠 둔다.
- 올렸던 초안은 `references/<시즌id>-<책>-초안.md`로 남긴다. 두 판을 비교해 배운 것을 `references/<시즌id>-<책>-수정에서-배운-것.md`에 적는다.
  다음 시즌에도 통할 규칙은 위 3-1과 검증 목록으로 옮긴다.
